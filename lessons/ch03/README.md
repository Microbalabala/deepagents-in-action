# 第 3 章课程讲义：虚拟文件系统与 Agent 上下文工程

本课程围绕 [Datawhale 第 3 章](https://datawhalechina.github.io/deepagents-in-action/chapters/ch03-virtual-filesystem/) 的主题展开，补充实现机制、可复现实验、生产设计与面试训练。它不是原文翻译，而是一套可以按顺序学习、验证和复盘的独立讲义。

**基线：2026-09-17，本项目实际安装 `deepagents==0.7.14`，Python 3.12。** 原始课程和在线文档可能随版本变化；涉及具体 API 时，以本文注明的本地源码和实测结果为准。不要将旧版示例、当前网页和本项目环境拼接使用。

所有代码仅作为 Markdown 代码块提供。编写本讲义没有修改项目业务源码、依赖声明、锁文件或模型配置。实验验证使用现有虚拟环境和临时目录，不调用收费模型服务，不读取项目密钥。

## 一、学完以后应该能做什么

1. 解释文件系统如何改变 Agent 的信息访问方式，以及它为什么不等同于 RAG、无限上下文或长期记忆。
2. 正确使用 `ls`、`read_file`、`write_file`、`edit_file`、`delete`、`glob`、`grep`，处理分页、截断、覆盖和失败。
3. 在相同工具调用序列下比较 State、Filesystem、Store 三种 Backend；验证同线程、不同线程、不同用户和对象重建后的可见性。
4. 用 CompositeBackend 组合任务草稿与长期资料，解释路由去前缀和最长前缀匹配。
5. 验证大工具结果卸载、原文回读与权限拒绝；理解它们的适用范围。
6. 设计可审计、可隔离、有并发控制的研究 Agent 文件架构。
7. 在面试中从机制、实验、故障和权衡四个层面回答问题，而不只是背出类名。

讲义覆盖常见中高级 Agent 工程与系统设计考点，但面试结果还取决于编码、基础知识、项目经验和岗位要求，不能由一章课程保证。

## 三、实验约定

### 3.1 代码的三种标签

- **完整可运行代码**：包含所需导入，或明确依赖第 03 部分的公共实验代码；复制到独立 Notebook 的同一内核即可执行。
- **接入示例**：需要用户提供模型、数据库或服务配置；文中明确说明未在本次编写过程中实际调用这些外部服务。
- **设计伪代码**：解释事务、并发或部署设计，不冒充完整 SDK 实现。

第 03 部分提供一份公共实验驱动。后续离线实验在同一 Notebook 中先运行它，再运行对应代码块。没有要求你在项目中创建 `.py` 文件。

### 3.2 实验目录与环境

磁盘实验使用 Python `TemporaryDirectory`，只操作专门的临时目录，退出实验后自动清理。需要测试跨进程持久化时，单独使用临时根目录并明确管理其生命周期。

实验不会因为运行了 `StateBackend` 就自动具备多轮保存能力；需要 Checkpointer，或显式把状态传入下一次调用。`InMemorySaver` 和 `InMemoryStore` 都只在当前进程内保存数据。

### 3.3 基本实验验收

- [ ] 七种文件工具都被真实执行，记录工具结果及成功/失败状态。
- [ ] 分页读取验证偏移和下一页，未把局部内容当作全文。
- [ ] 验证写入覆盖、精确替换歧义、字面量搜索和删除。
- [ ] State 与 Filesystem 使用相同文件、相同步骤比较；本课程额外测试 Store。
- [ ] 比较同线程、不同线程、重建对象和更换 namespace 的可见性。
- [ ] 至少一个实验检查实际文件/状态/Store 数据，而非只看 Agent 自述。
- [ ] 区分“已实测”“源码确认”“理论预期”和“需要外部服务验证”。

### 3.4 拓展验收

- [ ] Composite 的草稿和长期文件分流正确，能解释后端内部路径。
- [ ] 大工具结果被卸载，保存内容与原始内容一致，能定位中间证据。
- [ ] 权限拒绝覆盖创建、修改、删除；没有把工具权限当成 OS 沙箱。
- [ ] 综合任务包含证据索引、最终报告和评估表。
- [ ] 能讨论并发覆盖、幂等重试、租户隔离、检查点膨胀和检索完整性。

## 四、阅读时始终记住的三个问题

**信息在哪里？** 模型消息、图状态、磁盘、Store 是不同存储层。

**谁可以访问？** `thread_id`、namespace、路径路由、授权系统各有职责。

**有什么证据？** 模型说“写好了”不代表写入成功；工具成功也不代表搜索结果完整，更不代表结论正确。
